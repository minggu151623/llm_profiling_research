# What this study can establish

**Names have already been used for static branch-probability prediction.** In LLVM, Raman and Li embedded callee names from control-dependent blocks, alongside structural features, and trained against edge probabilities derived from SamplePGO. The PLATO group later described adding signature embeddings to GraalNN. The proposed contribution is a measured comparison of frozen SLM predictions and representations against structural and lexical predictors on the same original JVM bytecode jumps and input families. [Raman and Li, §4.3](https://arxiv.org/html/2202.06728) · [PLATO, Embeddings](https://plato.matf.bg.ac.rs/?content=research_graalvm_sprof) · [Registered protocol](../../experiments/study/protocol.md)

| Decision | What prior work already covers | What evidence the study needs |
| --- | --- | --- |
| Select structural baselines | Ball–Larus estimates direction from loops and other program cues. Wu–Larus combines heuristic evidence into probabilities. VESPA adapts learned regression to native binaries. GraalSP and GraalNN predict probabilities in Graal IR. [Ball–Larus](reading_notes/ball-larus.md) · [Wu–Larus](reading_notes/wu-larus.md) · [VESPA](reading_notes/vespa.md) · [GraalSP](reading_notes/graalsp.md) · [GraalNN](reading_notes/graalnn.md) | Score the fixed offset-direction heuristic, learned structural models and SLM on identical branch/workload rows. Report branch error per project. An actual Graal comparison requires a separate orientation-preserving edge mapping with reported coverage. |
| Isolate the value of names | Raman–Li already combines names and structural information. Method Names 2025 measures method hotness; CodeT5 recovers identifiers in source. PLATO describes an in-progress GraalNN extension using signature embeddings. [Raman–Li](reading_notes/raman-li.md) · [Method Names](reading_notes/method-names.md) · [CodeT5](reading_notes/codet5.md) · [PLATO](https://plato.matf.bg.ac.rs/?content=research_graalvm_sprof) | Pair full and masked representations on the exact same sites, and compare against structural plus lexical regression. A win over a constant alone gives weak evidence of semantic value. |
| Justify a zero-run SLM comparison | Phaedrus applies LLMs to dynamic function behavior using compiler analysis. [Phaedrus](reading_notes/phaedrus.md) | Evaluate local edge probabilities. Report how prompt scores are converted into probabilities, including calibration and residual errors. The Phaedrus function-level scores and compiler speedups address different endpoints. |
| Quantify transfer | Allamanis demonstrates sensitivity of evaluation to duplicated source code. [Allamanis](reading_notes/duplicates.md) | Keep project families together, fit transformations on training features and audit code overlap at split boundaries. Public training corpora of pretrained models can contain upstream code even after downstream deduplication. |
| Quantify workload sensitivity | Kim et al. use behavior observed in one profile to detect input dependence. Their main target is the change in accuracy of a branch predictor. [Kim et al.](reading_notes/kim-input.md) | Retain separate counts and coverage for both workloads. Estimate differences in taken fraction for the same class, method and original BCI. Report workload-shift and unseen-project scores separately. |

The empirical scope is selected library classes, controlled API calls, one fixed small model and specified baselines. Manuscript claims about which model performs better must point to paired results and uncertainty. Priority, production workload representativeness and compiler throughput require additional evidence.
